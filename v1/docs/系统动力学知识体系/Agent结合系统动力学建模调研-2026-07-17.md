# Agent 结合系统动力学建模：实例、证据强度与项目建议

> 调研日期：2026-07-17  
> 本文先回答“已有 Agent 如何参与建模”，再分析 Systematology。它优先记录原始论文、发表状态、实验与限制；结论按证据强度分层。

---

## 1. 结论摘要

截至本轮检索，**尚未找到一个已同行评审、端到端覆盖“检索证据 -> 协作建模 -> CLD/FCM/D2D -> 人类验证”的 Agent 系统**。最接近当前项目的直接实例是 2026 年的两篇 arXiv 预印本：它们让 LLM Agent 从文本构建反馈 FCM，但只在单一文章案例上评估，不能证明跨领域可靠性或替代建模者。

相反，以下证据较扎实但范围更窄：

- 两阶段 LLM CLD 提取证明了“变量识别 -> 因果边构建”的任务分解，在简单教学 CLD 上可接近专家图；
- System Dynamics Bot 在两套独立数据中只能识别约 60% 的变量链接与反馈回路；
- 2026 年的新 SD-AI benchmark 首次把 **CLD 抽取** 与 **模型讨论/建模辅导/错误修复** 分开测量，结果显示讨论与错误修复显著更难。

因此，当前项目不应以“已有成熟 Agent 范式”为前提。更严谨的方向是：

> **验证一个受系统动力学协议约束的 Agent，是否能在相同模型、相同语料下，优于两阶段 CLD 基线完成证据保留、迭代建模和结构批评。**

这是可证伪的研究问题，而不是先假定多 Agent 或 ReAct 编排天然有价值。

---

## 2. 先统一“Agent”含义

相关论文中的 agent 常指不同东西，若不区分会误判可复用性。

| 类型 | Agent 是什么 | 与 Systematology 的关系 |
|---|---|---|
| A. 建模 Agent | LLM 调用检索/建模/仿真工具，根据中间结果决定下一步 | 当前项目想研究的主体 |
| B. LLM 抽取器 | 使用多步 prompt 从文本生成 CLD/FCM；作者有时称其 agent | 可作为 CLD/FCM 生产能力，但不等于协作建模 |
| C. 模拟中的 Agent | ABM 中由 LLM 驱动的个体行为者 | 研究对象是被模拟的社会，不是协助人建模；不应与 A 混用 |
| D. 因果发现 Agent | 多 Agent 辩论、选择统计因果发现算法 | 可借鉴工具选择/质量门，但通常是无反馈环的 DAG 与数值数据问题 |

本项目应聚焦 **A**，用 **B** 提供候选结构；不能把 B 或 C 当成“Agent 已完成系统动力学建模”的证据。

## 3. 直接实例：Agent 从文本构建反馈 FCM

### 3.1 The Agentic Leash：最接近当前项目，但仅是预印本案例

**Panda, Adigun, Kosko, “The Agentic Leash: Extracting Causal Feedback Fuzzy Cognitive Maps with LLMs”.**  
arXiv: https://arxiv.org/abs/2601.00097 （v3，2025-12-31；arXiv 未列出期刊参考）

**它实际做了什么**

1. 同一 LLM 依次执行三组 system instructions：提取名词/名词短语 -> 从中筛选 FCM 概念节点 -> 遍历节点对并抽取或推断模糊因果边。
2. 将得到的 FCM 进行迭代，观察固定点或极限环；作者称 FCM 的平衡态可反过来驱动 Agent 取回和处理因果文本，因此称为“agentic leash”。
3. 分别用 Gemini 2.5 Pro 与 ChatGPT-4.1 生成 FCM，并以等权凸组合混合两个边矩阵。

**评估是什么**

- 输入是一篇关于 AI 的 Kissinger 等人文章及其中一个段落；人工也对同一段落构建了一个 4 节点、5 边 FCM。
- LLM 输出为 15/20 节点的 FCM；作者比较部分对应节点的极限环，报告二者都出现两步极限环。
- 论文自身承认，原文往往没有显式动力学，作者/读者也难以验证由文本导出的平衡态预测。

**证据判断：低，作为方法灵感而非可靠性依据。**

- 优点：三阶段 FCM 抽取、结构化 system instruction、模型混合、把反馈模型放回 Agent 循环，均与当前项目直接相关。
- 限制：单一文本案例；没有节点/边 precision-recall、没有跨语料实验、没有专家盲评、没有用户建模研究；“极限环相似”不等于结构或因果正确。
- 对项目的可复用部分仅限于：`名词短语 -> 可度量变量 -> 边` 的显式拆分，以及将“模型结果触发下一轮检索问题”作为待验证机制。

### 3.2 Agentic Chunking：最新直接后续，但仍未跨过验证门槛

**Panda, Adigun, Kosko, “Agentic Chunking and Bayesian De-chunking of AI Generated Fuzzy Cognitive Maps: A Model of the Thucydides Trap”.**  
arXiv: https://arxiv.org/abs/2605.17903 （2026-05-18）

**它实际做了什么**

- LLM Agent 将长文本切成重叠 chunk，分别抽取 chunk FCM，再用凸组合合并为循环 FCM；论文提出 operator-level 的“Bayesian de-chunking”。
- 案例是 Allison 关于 Thucydides Trap 的文章。作者报告在持续激活“崛起国野心与权利”节点时，8 个 FCM 中有 7 个给出战争类型的结果。

**证据判断：低。**

- 它是目前时间上最新、且明确处理长文本扩展性的直接 Agent-FCM 例子。
- 但它与 Agentic Leash 同一作者组、同为预印本、同样使用单篇理论文章；“7/8 预测战争”是模型内部情景结果，无法验证为真实世界预测。
- 可借鉴“chunk 级局部图 + 显式合并”，但必须改造成保留来源片段、语境和冲突的 `EvidenceClaim` 合并，不能仅平均边矩阵。

### 3.3 Causal Autoencoder-like Generation：不是文本建模 Agent

**“Causal Autoencoder-like Generation of Feedback Fuzzy Cognitive Maps with an LLM Agent”.**  
arXiv: https://arxiv.org/abs/2509.25593 （2025-09-29）

- 它将**已存在的 FCM**转成文本，再由 LLM 重建 FCM，重点是可解释中间表示与有损重构。
- 它不解决从研究证据建模、Agent 工具选择、用户协作或模型验证。
- 可作为 `CLD/FCM -> map-to-text -> 人工审查` 的辅助思路，不是当前项目的 Agent 架构依据。

## 4. CLD 自动建模：两阶段论文与可比较基线

### 4.1 两阶段 CLD 论文：你提到的实例，证据范围很明确

**Liu & Keith, “Leveraging Large Language Models for Automated Causal Loop Diagram Generation: Enhancing System Dynamics Modeling through Curated Prompting Techniques”.**  
arXiv: https://arxiv.org/abs/2503.21798 （2025-03-23；arXiv 版本，未列出期刊参考）

**方法**

- 比较 baseline、few-shot、guided prompt、two-stage 四种提示组合。
- two-stage 先输出方向性明确的变量，再基于变量和动态假设输出 DOT 格式的有符号因果边。

**实验**

- 44 个“动态假设-CLD”对，来自系统动力学教材；复杂度从单回路到 2-4 个反馈回路。
- 作者报告，对简单结构，精心设计的提示尤其是 two-stage 能生成接近专家 CLD 的结果。

**可靠性判断：中低，足以作为抽取基线，不足以支持完整 Agent。**

- 它比 Agentic Leash 更适合指导当前 CLD 实现：任务拆分清晰、输入输出可测、有人类专家参考图。
- 但它不是 Agent 系统：没有检索、状态、反思、工具调用或用户协作；模型为 `text-davinci-003`，数据规模与真实问题复杂度有限。
- 项目应复现其 two-stage 作为 **B1 基线**，而不是将其当作多 Agent 架构证明。

### 4.2 System Dynamics Bot：更直接的外部性能下限

**Hosseinichimeh et al., “From Text to Map: A System Dynamics Bot for Constructing Causal Loop Diagrams”.**  
arXiv: https://arxiv.org/abs/2402.11400 （2024-02-17；arXiv 版本）

**实验**

- 数据集 1：系统动力学文献中的 20 个 CLD 与文本。
- 数据集 2：30 位参与者对 vignette 的文字回答，以及 3 名系统动力学建模者编码的 CLD。
- Bot 在两套数据上识别约 60% 的变量链接和反馈回路。

**可靠性判断：中低，但有重要的负面基线价值。**

这说明“文本直接变图”离可替代人工建模仍有明显差距。Systematology 若没有相对该基线的改进，不能以 Agent 名义声称已提升建模质量。

### 4.3 Pipeline Algebra：已发表，但只验证专家修订而非 Agent 自治

**“LLM-Powered, Expert-Refined Causal Loop Diagramming via Pipeline Algebra”.**  
*Systems* (2025), DOI: https://doi.org/10.3390/systems13090784

- 将 LLM、计算、转换和执行表示为有类型、幂等运算，复用中间结果以获得可复现性。
- 在一个新型能源商业化案例中，资深系统动力学实践者指出初始图缺少最佳实践模式且过度依赖问题陈述；重写规则和迭代提示后才改善。
- 作者明确将定量验证留为未来工作。

**可靠性判断：中。** 该论文支持“版本化中间产物 + 专家修订”这类工程约束，不支持无人工的 Agent 判定。

## 5. 最新评测：Agent 应测“讨论与修复”，不能只测出图

### Benchmarking System Dynamics AI Assistants

**Leitch, “Benchmarking System Dynamics AI Assistants: Cloud Versus Local LLMs on CLD Extraction and Discussion”.**  
arXiv: https://arxiv.org/abs/2604.18566 （v2，2026-04-20）

这篇论文不是一个完整 Agent，但它提供了当前最贴近问题的评估资产。

| 基准 | 内容 | 关键发现 |
|---|---|---|
| CLD Leaderboard | 53 个结构化 CLD 抽取测试；要求变量、边方向、极性和约束精确匹配 | 云模型总体通过率为 77-89%；这不是“接近专家”这种主观判断，而是严格结构匹配 |
| Discussion Leaderboard | 模型建构步骤辅导、反馈解释、模型错误修复 | 最佳局部模型在建模步骤可达 100%，反馈解释为 47-75%，错误修复仅 0-50% |

论文的直接价值是揭示三种能力不可混为一谈：

1. 生成 JSON/抽取边；
2. 解释反馈；
3. 审查并修复已有模型。

当前项目若要称为 Agent，应至少同时评测这三项，而不是只测 Specialist 是否返回 Schema。

**限制也必须保留**：这是 arXiv 预印本；所有运行使用单一随机种子，因果推理子类仅 3 个测试，且大部分部署比较在单台 Mac Studio 上进行。它适合作为可复现的起点，不是模型能力的最终排名。

## 6. 相邻 Agent 研究：可借鉴，但不是系统动力学证据

| 工作 | 状态 | 可借鉴 | 不能外推的部分 |
|---|---|---|---|
| **CausalMapper** (2023), *Creativity and Cognition*, DOI `10.1145/3591196.3596818` | 同行评审会议论文 | LLM + 因果图的 mixed-initiative 交互，强调让用户用领域知识纠正模型偏差 | 面向设计思维教学，不是 CLD/FCM/D2D 的性能验证 |
| **CausalChat** (2025), *IEEE TVCG*, DOI `10.1109/TVCG.2025.3602448` | 同行评审期刊论文 | 通过变量对递归探索潜变量、混杂和中介；文字解释与可视图绑定；有用户研究 | 是因果网络交互工具，不是反馈动力学模型或证据综合器 |
| **Multi-Agent Causal Discovery Using LLMs** (2024), arXiv `2407.15073` | 预印本 | LLM 正反方辩论与统计因果发现算法选择；在 5 个基准上报 F1/SHD/NHD | 目标是数据驱动 DAG 因果发现，不处理反馈回路、系统动力学语义或人机建模 |
| **Structured knowledge-based causal discovery: Agentic streams of thought** (2025), *Information Processing & Management*, DOI `10.1016/j.ipm.2025.104202` | 同行评审期刊论文 | 分层任务分解、方向/传递性处理、双层质量门 | 同样是 causal discovery，不可把其基准成绩迁移为 CLD/FCM 能力 |

另需避免一个常见混淆：Generative Agent-Based Modeling 或 Smart Agent-Based Modeling 中的 LLM agent 是**仿真里被建模的行为个体**。它们研究“如何让虚拟人行动”，不是“如何帮助研究者构建系统动力学模型”。

## 7. 对当前 Systematology 的逐项分析

### 7.1 当前实现与这些实例的真实关系

当前 `LeadAgent` 是一个 ReAct 工具编排器：它将输入 documents 传给 `run_cld_analysis`，再调用 FCM/D2D 工具；`RunContext` 只记录缓存、预算和工具调用。CLD 子系统是“视角生成 -> Specialist 并行提取 -> 节点归并 -> 冲突检测 -> Judge”。

这意味着当前实现：

- **已经具备**：结构化输出、CLD 后再进行后续分析的依赖守卫、并行候选抽取、基本的失败记录。
- **尚不具备 Agentic Leash 的直接机制**：由模型结果驱动的检索/再建模循环，或 chunk 级模型合并。
- **更重要地尚不具备**：边级证据、模型版本、迭代编辑保真、用户审查状态、结构批评任务和对上述能力的独立评测。

因此，当前的 ReAct 调度不应被描述为“已经实现了系统动力学建模 Agent”。更准确的表述是：**它是一个可作为实验底座的自动化原型。**

### 7.2 不应直接照搬的部分

| 外部方案 | 不建议直接采用 | 原因 |
|---|---|---|
| Agentic Leash 的“平衡态驱动 Agent” | 让 FCM 自主决定检索和结构更新 | 现有证据无法证明该闭环提升事实正确性；模型内部平衡态会放大初始文本偏差 |
| Agentic Chunking 的凸组合 | 直接平均各 chunk/Agent 的 FCM 权重 | 会抹去研究设计、语境、反证和语义不一致；需先做来源可追溯的概念对齐 |
| 多 Agent 多数投票 | 作为冲突边的最终裁决 | 投票不是独立证据，且会把少数但重要的利益相关者视角误判为噪声 |
| causal discovery 的 DAG 指标 | 直接作为 CLD 成功指标 | CLD 有反馈、延迟和定性关系；DAG 的无环假设不成立 |

### 7.3 应直接采用的部分

| 来源 | 当前项目的具体改造 |
|---|---|
| Liu & Keith two-stage | 把 `Specialist` 固定为变量/方向性命名阶段和边/极性阶段；与单次抽取做消融比较 |
| System Dynamics Bot | 以约 60% 链接/回路识别作为必须超过的公开基线，而非只比较内部 prompt |
| SD-AI Benchmark | 将 CLD 抽取、反馈解释、迭代编辑、错误修复拆成独立测试；特别测试“修改图时保留已有正确边” |
| Pipeline Algebra | 对每次抽取、合并、审查和仿真保留幂等中间产物和版本，不让 Agent 只在上下文中记忆模型 |
| CausalMapper / CausalChat | 在核心准确性通过后，设计局部变量对探索与可见理由，而非先打造聊天外观 |

## 8. 建议：把“Agent 是否有价值”变为可测的主研究问题

### 8.1 建议的主问题

> 在相同 LLM、相同冻结语料和相同系统动力学任务上，受协议约束的 Agent（可检索、保留证据、迭代编辑、结构批评）是否能优于 two-stage CLD baseline，并让用户更准确地发现和修复模型假设？

这一定义将“Agent”限制为可观察行为，而不是框架名称：它必须维护状态、选择下一步验证动作、利用中间产物，并能被逐项评测。

### 8.2 最小实验设计

| 组别 | 能力 | 用途 |
|---|---|---|
| B0：single-shot | 一次文本 -> CLD | 测量基础生成能力 |
| B1：two-stage | 变量 -> 边；复现 Liu & Keith 的核心设计 | 当前必须具备的强基线 |
| A1：protocol Agent | B1 + `EvidenceClaim` + 迭代修改保真 + 结构批评 + 明确停止条件 | 测量 Agent 增量价值 |
| A2：多角色 Agent（后续） | A1 + 独立证据检索/批评上下文 | 只在 A1 已证明价值后测试多 Agent 是否进一步有效 |

共同评测：

- CLD：节点 F1、带方向/极性的边 F1、回路识别、图编辑距离；
- 证据：每条边的来源定位准确率、支持/反对证据保留率；
- 迭代：新增信息后保留原有正确边的比例；
- 讨论：反馈解释正确率、模型错误修复建议的专家接受率；
- 人机协作：用户是否能说出关键边界和假设，而不是只报告满意度。

### 8.3 实施优先级

1. **先实现/评测 B1，不先扩充 Agent 数量。** 将当前 Specialist 改为严格 two-stage，并建立外部/人工黄金集。
2. **为 A1 建立证据与版本状态。** `RunContext` 不能只缓存 `SharedCLD`；至少新增 `EvidenceClaim`、边审查状态、图版本和编辑日志。
3. **实现一个可测的结构批评动作。** 先问“这张图少了什么反馈、延迟、存量或边界条件”，并与 SD-AI Discussion 类任务比较；不要把 Judge 设为投票终点。
4. **再实验 Agentic Chunking。** 仅当长语料是实际瓶颈时，用 chunk 生成候选子图；合并时保留每条边的文本来源，不做无来源的矩阵平均。
5. **最后接 D2D。** D2D 的输入应是已通过结构/变量类型审查的模型；它不是用来补偿前面抽取不可靠的工具。

## 9. 需要继续精读的顺序

1. **Agentic Leash**：精读三条 system instruction、人工 FCM 对比和其对无监督抽取的主张；结论必须标记为单例预印本。
2. **Agentic Chunking**：精读 chunk overlap、概念对齐、凸组合和“Bayesian de-chunking”；仅提取可替换为证据保留的机制。
3. **SD-AI Benchmark**：直接取得其 53 个 CLD 与 Discussion 测试、ground truth schema、运行配置；这是项目近期最有价值的评测资产。
4. **Liu & Keith + System Dynamics Bot**：将 two-stage 与约 60% 的外部表现固化为 B1/下限基线。
5. **CausalChat / CausalMapper**：在核心评测通过后才研究 UI 和协作流程，避免“交互很好看但模型不可靠”。
