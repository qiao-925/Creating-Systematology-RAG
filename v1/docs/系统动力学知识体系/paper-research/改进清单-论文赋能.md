# 改进清单：论文赋能 Systematology 项目

> 来源：论文精读 + 架构评估
> 创建：2026-05-31
> 定位：持续增长的改进项追踪，每读完一篇相关论文后补充

---

## 来源：LLM-CLD-2503.21798 (ISDC 2024)

### P0 — 论文核心发现，当前未采用

- [ ] **引入两阶段 prompt 方法（论文核心贡献）** — 将 Specialist 的 `extract_causal_links()` 从单次 nodes+links 提取拆为两次 LLM 调用：
  - 阶段 1：只提取变量，要求"变量名应具有方向性（增加/减少含义明确）"
  - 阶段 2：基于阶段 1 变量列表 + 原始文本，构建因果连接
  - 涉及文件：`backend/core/modules/cld/specialist.py`
  - 论文依据：两阶段在三个测试案例中均优于其他方法，尤其改善外生变量识别和因果方向判断

- [ ] **变量命名的"方向性"约束** — 当前 Specialist prompt 未要求变量名具有方向性。论文强调"Choose names for which the meaning of an increase or decrease is clear"，这应在阶段 1 单独 prompt 中作为硬性约束
  - 涉及文件：`backend/core/modules/cld/specialist.py`

### P1 — 论文启发，当前模块闲置或未集成

- [ ] **Guardrail 体系接入 pipeline** — 5 个守卫函数已实现但零调用点。至少应接入：
  - `check_pipeline_rail` → FCM/D2D 工具调用前
  - `check_budget` → 每次 LLM 调用前
  - `check_self_review` → CLD 产出后（与 judge 门控配合）
  - 涉及文件：`backend/core/orchestration/tools.py`, `backend/core/orchestration/guardrails.py`

- [ ] **DOT/Digraph 作为中间表示（IR）** — 论文用 Graphviz DOT 作为 CLD 的标准化文本表示。我们的 SharedCLD 已承载等价的图信息，但缺少 DOT 序列化/反序列化。增加后可：
  - 与外部 SD 工具（Vensim、Stella）互操作
  - 作为可视化渲染的标准输入（已有 SVG 渲染能力）
  - 涉及文件：`backend/core/models.py`（新增 `to_dot()` / `from_dot()` 方法）

- [ ] **GMB 场景的 Multi-Agent 架构设计** — 论文明确指出 Group Model-Building 是核心应用场景。我们当前的视角系统（DDC 分类 + 多 Specialist）是 GMB 的雏形，但尚未针对多利益相关者场景设计专门的 Agent 角色
  - 涉及：架构设计文档，非代码改动

### P2 — 架构评估发现的偏离（非论文直接相关）

- [ ] **节点归并接入 sentence-transformers** — `merge.py` 声称不需要但架构承诺了。两种方案：
  - A）接入 MiniLM-L6-v2（与架构一致），阈值 0.8
  - B）更新架构文档承认纯字符串方案（降低维护负担）
  - 涉及文件：`backend/core/modules/cld/merge.py`

- [ ] **FCM rater.py 接入 pipeline** — LLM 7 级边权重评级已实现但 `run_fcm_analysis` 只用静态映射表
  - 涉及文件：`backend/core/modules/fcm/rater.py`, `backend/core/orchestration/tools.py`

- [ ] **D2D uncertainty.py 接入 pipeline** — 置信度传播已实现但未被调用
  - 涉及文件：`backend/core/modules/d2d/uncertainty.py`, `backend/core/orchestration/tools.py`

- [ ] **输入管线（HyDE + 多查询）接入 Lead Agent** — `input/pipeline.py` 完整实现但 Lead Agent 直接传原始问题
  - 涉及文件：`backend/core/orchestration/lead_agent.py`, `backend/core/input/pipeline.py`

- [ ] **DDC 分类器接入 LLM** — `_llm_classify()` 是空实现，当前仅 30 词条的关键词匹配
  - 涉及文件：`backend/core/modules/cld/perspectives/classifier.py`

- [ ] **D2D 敏感度分析消费 FCM 权重矩阵** — 当前从 SharedCLD 边独立重建权重，不从 `WeightedFCM.weight_matrix` 读取。rater 接入后会导致 D2D/FCM 权重不一致
  - 涉及文件：`backend/core/modules/d2d/sensitivity.py`

### P3 — 论文方法论缺陷，需在项目中避免

- [ ] **建立量化评估体系** — 论文只用定性视觉比较。项目应引入：图编辑距离（GED）、节点 F1、边 F1、回路完整性等指标
  - 涉及：新文件，评估模块

- [ ] **建立错误类型学** — 论文的失败模式分析是非系统的（按案例叙述）。项目应建立结构化的错误分类：外生变量遗漏、因果方向反转、变量名非方向性、回路遗漏、关系类型错误
  - 涉及：文档或评估模块

- [ ] **支持迭代修正循环** — 论文只做单次生成。项目应探索"生成 → 评估 → 修正"的迭代模式，利用 Judge + guardrail 反馈驱动二次修正
  - 涉及：`backend/core/orchestration/lead_agent.py`
