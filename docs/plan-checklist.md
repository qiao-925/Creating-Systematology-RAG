# Plan 文档模板

> 面向 MVP 构建和版本迭代的主线开发计划。7 个章节，清单格式。

## 版本目标

说明这个版本要交付什么、为什么现在做。

```markdown
## 版本目标

- 做什么：交付一条稳定的 CLD → FCM → D2D 主链路
- 为什么：当前系统缺乏结构化的因果分析能力，需要先跑通核心流程再迭代
```

列出本计划关联的架构文档和需要同步更新的文档。计划执行完毕后，锚定文档必须同步更新。

```markdown
## 文档锚定

- 锚定：`README.md` — 用户入口

- 同步：`AGENTS.md` — Agent 执行地图需更新
```

## 决策清单

记录技术选型和方案取舍。分两层：核心决策（影响架构方向）和支撑决策（实现细节）。

```markdown
## 决策清单

### 核心决策
- [x] D1 编排框架：选项 A LlamaIndex AgentWorkflow / B 自定义编排器 → 选 A，复用现有样板
- [ ] D2 FCM 引擎：选项 A FCMpy / B NumPy 直接实现 → 待决

### 支撑决策
- [x] D3 节点归并阈值：选项 A 0.8 / B 0.7 → 选 A，保守策略
```

状态：`[x]` 已闭合 / `[ ]` 待决

## 任务清单

拆分版本内的具体工作。分阶段组织，每阶段有明确交付物。

```markdown
## 任务清单

### 阶段 1：基础骨架
- [ ] T1 实现 CLD 模块
  - 产出：modules/cld/module.py
  - 验收：输入研究问题，输出 SharedCLD
  - 失败路径：降级 — 用 placeholder 先跑通链路

### 阶段 2：衍生分析
- [ ] T2 实现 FCM 仿真
  - 产出：modules/fcm/simulator.py
  - 验收：Kosko 迭代收敛，输出稳定态
  - 失败路径：重试 — 调整收敛阈值
```

失败路径选项：
- 重试：同方案再试一次
- 降级：用更简单的方案替代
- 升级：标记为阻塞，需要人类决策
- 跳过：不影响主路径，可以后续补

## 执行规则

定义 agent 执行计划时的行为约束。分两层：硬性约束（违反则任务失败）和建议项（agent 判断）。

```markdown
## 执行规则

> 本节定义 agent 执行计划时的行为约束，优先级高于任务清单中的任何描述。

### 硬性约束（违反则任务失败）

1. **逐任务执行** — 按任务顺序依次执行，每个任务完成后再进入下一个
2. **强制自检** — 每个任务完成后，对照验收标准逐项自检，未通过的项触发对应失败路径
3. **输出交付物** — 每个任务完成后输出该任务的产出物和自检结果

### 自主推进规则

- **默认行为**：自检通过后自动继续下一个任务，无需等待人类确认
- **需确认的任务**：任务清单中标注 `[需确认]` 的任务，完成后必须等待人类确认再继续
- **失败升级**：自检未通过且失败路径无法解决时，暂停并升级给人类

### 建议项（agent 判断）

- 遇到不确定时优先记录而非跳过
- 保持中间产物的可追溯性
```

```markdown

> 执行时按任务填入 agent prompt，每个任务独立执行。

### 通用模板

读取 `{plan_path}`。

当前执行任务：T{X.X} {任务名称}

硬性约束：
- {从执行规则节提取}

自主推进规则：
- 自检通过 → 自动继续下一个任务
- 任务标注 [需确认] → 等待人类确认
- 自检失败且失败路径无法解决 → 暂停升级

验收标准：
- {从任务清单的当前任务提取}

失败路径：
- {从任务清单的当前任务提取}

参考资源：
- {从文档锚定节提取相关文档}
```
