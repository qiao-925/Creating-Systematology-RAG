# Plan 文档模板

> 面向 MVP 构建和版本迭代的主线开发计划。6 个章节，清单格式。

## 版本目标

说明这个版本要交付什么、为什么现在做。

```markdown
## 版本目标

- 做什么：交付一条稳定的 CLD → FCM → D2D 主链路
- 为什么：当前系统缺乏结构化的因果分析能力，需要先跑通核心流程再迭代
```

## 文档锚定

列出本计划关联的架构文档和需要同步更新的文档。计划执行完毕后，锚定文档必须同步更新。

```markdown
## 文档锚定

- 锚定：`ARCHITECTURE.md` — 主链路架构定义
- 锚定：`README.md` — 用户入口
- 同步：`docs/api.md` — 新增 API 需补充
- 同步：`AGENTS.md` — Agent 执行地图需更新
```

## 决策清单

记录技术选型和方案取舍。分两层：核心决策（影响架构方向）和支撑决策（实现细节）。

```markdown
## 决策清单

### 核心决策
- [x] D1 编排框架：选项 A LlamaIndex AgentWorkflow / B 自定义编排器 → 选 A，复用现有样板
- [ ] D2 FCM 引擎：选项 A FCMpy / B NumPy 直接实现 → 待决

### 支撑决策
- [x] D3 节点归并阈值：选项 A 0.8 / B 0.7 → 选 A，保守策略
```

状态：`[x]` 已闭合 / `[ ]` 待决

## 任务清单

拆分版本内的具体工作。分阶段组织，每阶段有明确交付物。

```markdown
## 任务清单

### 阶段 1：基础骨架
- [ ] T1 实现 CLD 模块
  - 产出：modules/cld/module.py
  - 验收：输入研究问题，输出 SharedCLD
  - 失败路径：降级 — 用 placeholder 先跑通链路

### 阶段 2：衍生分析
- [ ] T2 实现 FCM 仿真
  - 产出：modules/fcm/simulator.py
  - 验收：Kosko 迭代收敛，输出稳定态
  - 失败路径：重试 — 调整收敛阈值
```

失败路径选项：
- 重试：同方案再试一次
- 降级：用更简单的方案替代
- 升级：标记为阻塞，需要人类决策
- 跳过：不影响主路径，可以后续补
