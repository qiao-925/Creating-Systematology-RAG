# 版本规划文档

> 本文档沉淀 `ARCHITECTURE.md` 中与版本阶段、演进路线、实现计划关系相关的内容。

## 1. 版本总目标

围绕“运行流程为主轴”的统一架构，逐步从现状演进为可审计、可替换、可扩展的 CLDFlow 体系。

## 2. 版本阶段

### Phase 1 当前阶段

- 以 FCM 为默认衍生路径
- 建立 Lead Agent + CLD + FCM + D2D 主链路
- 保证 CLD 前置与护栏生效
- 建立失败终态与可观测性

### Phase 2a

- FCM 模块化
- 统一工具接口
- 建立模块元数据基础

### Phase 2b

- 引入 CLD / D2D 工具层进一步解耦
- 增强运行时选择逻辑
- 支持更细粒度降级

### Phase 3

- 引入 SD / 贝叶斯候选工具
- 基于元数据自主选择
- 强化审计、可替换性与适用范围扩展

## 3. 与实现计划文档的关联

`docs/implementation-plan.md` 负责回答：

- 如何落位
- 如何拆模块
- 如何定义接口
- 如何实现护栏

`docs/version-plan.md` 负责回答：

- 先做什么
- 后做什么
- 每个阶段的能力边界是什么
- 哪些变化需要保持对实现计划的引用关系

### 3.1 关联规则

- 版本规划中的每个 Phase 必须能映射到实现计划中的具体内容
- 版本规划不重复展开实现细节，只标记阶段目标与约束
- 实现计划中的阶段实施步骤应引用版本规划中的 Phase 编号

## 4. 版本与交付建议

- 当前版本以 Phase 1 为准
- 后续扩展优先沿着 Phase 2a → 2b → 3 演进
- 若发生架构决策调整，应先更新 `version-plan.md`，再同步 `implementation-plan.md`
