# Runtime Page 设计稿生成计划 V1

## 版本目标

- 做什么：为 CLDFlow 的 Runtime Page（运行时交互页面）生成 Figma 设计稿，覆盖用户输入问题 → 系统实时执行分析 → 渐进式展示结果的完整交互流程
- 为什么：Runtime Page 是用户与 CLDFlow 的主要交互入口，承载实时对话、Thinking 进度、CLD 可视化、Source 引用等核心体验。参考 DeepSeek、Manus 等问答型 Agent 的设计风格，打造专业且可信赖的分析工具界面
- 交付物：Figma 设计稿文件，包含 Runtime Page 的桌面端和移动端设计
- 设计风格参考：DeepSeek（深色专业风格、实时推理展示）、Manus（任务流程可视化、步骤式进度）

## 执行规则

> 本节定义 agent 执行计划时的行为约束，优先级高于任务清单中的任何描述。

### 硬性约束（违反则任务失败）

1. **逐任务执行** — 按任务顺序依次执行，每个任务完成后再进入下一个
2. **强制自检** — 每个任务完成后，对照验收标准逐项自检，未通过的项触发对应失败路径
3. **全量完成** — 执行所有任务后再输出最终结果，中间过程不需要报告
4. **失败升级** — 触发失败路径后仍无法解决的，记录原因并继续后续任务，最终汇总到交付物中
5. **反模式红线** — 生成的设计不得出现附录 B 中的任何一项
6. **风格一致性** — 共享组件必须与 Report Page 保持视觉一致

### 自主推进规则

- **默认行为**：自检通过后自动继续下一个任务，无需等待人类确认
- **需确认的任务**：任务清单中标注 `[需确认]` 的任务，完成后必须等待人类确认再继续
- **失败升级**：自检未通过且失败路径无法解决时，暂停并升级给人类
- **里程碑检查**：每个 Phase 完成后，输出阶段总结，确认方向正确再继续

### 禁止行为

- 跳过自检直接进入下一个任务
- 遇到不确定时自行跳过而非记录
- 忽略反模式清单（附录 B）中的任何一项
- 未完成所有任务就停止
- 与 Report Page 的共享组件视觉不一致

## 附录 B：反模式底线

> 以下为设计中必须避免的模式，无论设计方向如何。agent 生成设计时逐项对照，出现任何一项则判定任务失败。

- 紫色渐变 + 白卡片 + 大圆角
- 无差别阴影堆叠
- 只换 accent 色不改布局
- hero section 式首屏堆砌
- 过度装饰的插画/噪点纹理
- 所有内容做成对话气泡（CLDFlow 是分析工具，不是聊天机器人）
- 只有粗骨架没有实现细节
- 隐藏 Thinking 分析过程（用户需要看到系统"正在做什么"）
- CLD 因果图空间不足（节点数可达 50-100+）

| 组件 | Runtime Page | Report Page | 复用策略 |
|------|-------------|-------------|----------|

| Thinking | 实时进度展示 | 结果回顾展示 | 共享样式，交互逻辑不同 |
| CLD Canvas | 实时生成 + 交互 | 最终结果展示 | 共享画布组件，交互模式不同 |
| Input Bar | 追问入口 | 无（报告页无输入） | Runtime 独有 |
| Source Cards | 行内引用 | 独立卡片区域 | 共享数据模型，展示形式不同 |
| Leverage Table | 对话流内嵌入 | 独立表格区域 | 共享数据模型，展示形式不同 |
