# Plan 执行规则

执行 plan 文档中的任务时，必须遵循以下流程。

## 执行前

1. 读取完整的 plan 文档
2. 找到"执行规则"节，提取硬性约束
3. 找到"执行 prompt 模板"节，作为执行框架
4. 确认当前要执行的任务编号（T{X.X}）

## 单任务执行流程

1. **提取** — 从任务清单中提取当前任务的：产出、验收标准、失败路径
2. **约束加载** — 从执行规则节提取硬性约束，拼接到任务 prompt
3. **执行** — 完成任务产出
4. **自检** — 对照验收标准逐项检查（代码/构建层面）
5. **用户视角验证** — 从用户实际体验出发验证交付物：用户看到/用到的是什么？能否正常工作？build 通过不等于交付正确，必须确认用户视角下的结果符合预期
6. **输出** — 输出该任务的交付物和自检结果
7. **推进判断** — 自检通过 → 继续下一个任务；任务标注 `[需确认]` → 等待人类确认；自检失败且失败路径无法解决 → 暂停升级

## 不可跳过的步骤

- 自检（步骤 4）不得跳过
- 用户视角验证（步骤 5）不得跳过 — build 通过 ≠ 交付正确，必须从用户角度确认
- 输出交付物（步骤 6）不得跳过
- 推进判断（步骤 7）不得跳过 — 必须按规则决定是继续、等待还是升级

## 任务范围化原则

- 每次只执行一个任务（T{X.X}），不跨任务
- 不因"效率"而合并多个任务
- 上一个任务的自检未完成时不得开始下一个
